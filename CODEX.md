# Project: AI World — Minimal Autonomous AI Agent Simulation

I want you to build the first working prototype of an experimental 2D artificial-life simulation.

The long-term project will be a 2D world populated by autonomous AI agents powered by different LLMs such as OpenAI models, Gemini, DeepSeek, and local Qwen/Ollama models.

However, DO NOT build the long-term features yet.

For this version, focus on creating the smallest clean architecture that proves that AI-controlled people can perceive a 2D world, send their state to an AI backend, receive a structured decision, and execute that decision inside the game.

## Technology

Use:

* Godot 4.x
* GDScript
* Python 3
* FastAPI
* OpenAI Python SDK
* HTTP + JSON between Godot and FastAPI
* python-dotenv for environment variables

Do NOT use:

* databases
* Docker
* WebSockets
* vector databases
* LangChain
* complex agent frameworks
* authentication systems
* unnecessary abstractions

Keep V1 small, readable, modular, and easy to extend.

# 1. Create a minimal 2D world

Create a simple Godot 2D scene.

Do not use external graphical assets.

Use basic Godot shapes, polygons, labels, or simple generated visuals.

The world should visually contain:

* Alice
* Bob
* one Apple

Make it visually obvious which object is which using labels.

Something conceptually like:

```
    Alice

      ●


                     ●
                    Bob


           Apple
             ●
```

Use a simple background.

The purpose is functionality, not graphics.

# 2. Agent scene

Create a reusable `Agent` scene based on CharacterBody2D.

Each agent should have at minimum:

* visible body
* name label
* status/action label

Agent state should include:

* id
* agent_name
* hunger
* energy
* personality
* current_action
* position

Example:

Alice:

* hunger = 80
* energy = 100
* personality = friendly, cooperative, curious

Bob:

* hunger = 80
* energy = 100
* personality = selfish, suspicious, risk-taking

Make these values easy to configure per agent.

---

# 3. Available actions

For V1, agents may ONLY choose from:

* take_apple
* talk
* wander
* wait

Do not allow arbitrary actions generated by an LLM.

Use an enum or another centralized definition if appropriate.

Godot must validate every returned action before executing it.

Unknown/invalid actions should become `wait`.

---

# 4. Apple

Create one simple interactable Apple object.

The apple should have:

* id
* position
* available/taken state

Only one agent can successfully take the apple.

When an agent takes the apple:

* apple becomes unavailable
* apple disappears visually
* the agent's hunger decreases

For example:

hunger = max(0, hunger - 50)

The server does NOT decide whether the action physically succeeds.

Godot is authoritative.

This is important.

If Alice and Bob both decide to take the apple, Godot determines who actually succeeds based on execution order/world state.

# 6. FastAPI server

Create a FastAPI backend.

Required endpoint:

GET /health

Response:

{
"status": "ok"
}

Required endpoint:

POST /decide

Input:
AgentState

Output:
AgentDecision

Use Pydantic models.

Example response:

{
"agent_id": "alice",
"action": "take_apple",
"target_id": "apple_1",
"message": null,
"reason": "I am hungry and food is available."
}

The `reason` exists for debugging/observability only.

Godot should not execute the reason.

# 7. Fake AI mode

This is REQUIRED.

The project must work without an OpenAI API key.

Create an environment variable such as:

AI_PROVIDER=fake

When using fake mode, implement simple deterministic decision logic.

Example:

if hunger > 70 and apple is visible:
take_apple
elif another agent is visible:
talk
else:
wander

This allows us to test:

Godot
→ HTTP
→ FastAPI
→ decision
→ Godot

without involving an external LLM.

# 8. OpenAI provider

Also implement:

AI_PROVIDER=openai

Read the API key from:

OPENAI_API_KEY

Read the model name from an environment variable:

OPENAI_MODEL

Provide a sensible example/default configuration in `.env.example`, but keep the model configurable rather than tightly coupling the project to one particular model.

Never hardcode the API key.

Never expose the API key to Godot.

Use the current official OpenAI Python SDK API.

Use structured output / schema-constrained output if supported by the selected model/API.

The LLM must return a structure matching AgentDecision.

The model should receive:

* agent identity
* personality
* hunger
* energy
* perceived entities
* available actions

System behavior should communicate:

"You control one person in a simulated world.

You may only choose from the supplied available actions.

You cannot change world state directly.

You cannot invent objects.

You cannot invent actions.

The game engine determines whether an action succeeds.

Choose one action based on your personality, needs, and current observations."

Keep prompts concise to minimize token usage.

# 9. AI Client in Godot

Implement an `AIClient` responsible for communication with FastAPI.

Server URL should be configurable.

Default:

http://127.0.0.1:8000

It should POST AgentState JSON to:

/decide

and parse AgentDecision.

Handle:

* server unavailable
* timeout
* invalid JSON
* HTTP errors
* invalid actions

An AI failure must NOT crash or freeze the game.

Fallback action:

wait

---

# 10. Decision timing

Do NOT query the AI every frame.

Each agent should make high-level decisions at a configurable interval.

For the prototype use something like:

5 seconds

Add a little randomness/jitter if useful so Alice and Bob do not always send requests simultaneously.

The game should remain responsive while waiting for HTTP responses.

Do not block the main Godot thread.

---

# 11. Execute actions

Implement simple behavior for the four actions.

## wait

Agent stays still.

Status label:

Waiting

## wander

Choose a nearby random destination and move toward it.

Use simple CharacterBody2D movement.

Do not ask the LLM for individual movement directions.

The AI decides "wander".

Godot executes movement.

## take_apple

If the apple:

* exists
* is available
* is close enough

take it.

Otherwise the action fails safely.

When successful:

* remove/hide apple
* mark it taken
* reduce hunger

## talk

Agent approaches or interacts with another agent.

For this prototype, a full LLM-to-LLM conversation system is NOT required.

A simple message returned by the AI may be displayed above the agent or in the debug/event log.

Example:

Alice:
"Bob, do you think we should share the food?"

If using fake mode, generate a simple predefined message.

# Important architecture rule

Separate:

1. Intent
2. Execution

Example:

AI:

{
"action": "take_apple",
"target_id": "apple_1"
}

does NOT mean the apple was taken.

Godot performs:

validate target exists
→ validate target available
→ validate distance
→ execute
→ update world

Similarly:

AI:
{
"action": "wander"
}

Godot chooses the actual coordinates/path.

The LLM should make high-level decisions, while deterministic game systems execute them.
